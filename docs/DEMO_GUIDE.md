# Demo Guide and Onboarding Plan

Do not build a demo walkthrough yet.

This document exists so we know what the eventual guide should do after the core app structure exists. The guide should teach the finished core loop, not compensate for unfinished navigation.

## Build timing

The demo/onboarding guide should come after these exist:

1. Today screen
2. Garden zones
3. Simple Log flow
4. Guide/resource area
5. Clear mobile navigation

Until then, do not spend implementation time on a walkthrough, tour overlay, or demo room.

## Goal

When built later, the guide should help Momma D quickly understand:

- what the app is for
- what she should check first
- how to read recommendations
- how to log notes/photos
- where to find plant and garden guidance
- how to get value without using every feature

## Tone

Use warm, plain language.

Avoid:

- technical setup language
- “AI-powered” hype
- dense scientific explanations up front
- too many choices

Prefer:

- “Here’s what matters today.”
- “This is where your garden lives.”
- “Tap this when you notice something.”
- “The science is there when you want it.”

## Future first-run walkthrough

The first-run guide should be short. Recommended flow after the core app exists:

### Step 1: Welcome

Title: Welcome to Momma D’s Garden

Message: This is your simple garden helper. It keeps track of what is growing, what needs attention, and why each step matters.

Primary action: Show me around

Secondary action: Skip for now

### Step 2: Today

Title: Start with Today

Message: This screen tells you the most important garden actions right now, like watering pots, checking vines, or harvesting herbs.

Highlight: Today’s garden brief

### Step 3: Garden Zones

Title: Your garden is organized by space

Message: Pots, in-ground beds, raised beds, and trellises all behave differently. The app keeps advice tied to the real place where each plant grows.

Highlight: Garden / Zones

### Step 4: Smart Tips

Title: Science made useful

Message: Some cards explain the reason behind the advice. You can read the short action first and open the deeper science only when you want it.

Highlight: Botanist note / Why this matters

### Step 5: Garden Log

Title: Keep simple notes

Message: Add a quick note or photo when something changes. The app should help remember the season without making logging feel like homework.

Highlight: Log button

### Step 6: Done

Title: You’re ready

Message: Open the app when you want to know what matters today. You do not need to use every feature.

Primary action: Go to Today

## Returning-user guide

The Guide area should eventually contain a short “How to use this app” section:

1. Check Today first.
2. Look at Garden when deciding where something goes.
3. Use Log when something changes.
4. Open Guide when you want the why.

## Demo/prototype mode

Prototype data can be public while the UX is being shaped. Real persisted Momma D garden data must be private and protected.

Before real persistence is rebuilt, the app can label prototype data gently.

Recommended copy:

- “Sample garden plan”
- “This preview is based on Momma D’s backyard structure.”
- “Real saved garden data comes later.”

Avoid making prototype mode feel broken or temporary. It should feel like a useful preview.

## Progressive disclosure

Do not explain everything at once.

Use layers:

1. Action summary
2. Short reason
3. Optional science
4. Optional detailed guide

## Help prompts

Small contextual prompts can help later:

- On Today: “Start here when you only have a minute.”
- On Garden: “Plants behave differently in pots, ground beds, and raised beds.”
- On Log: “A quick photo today can explain a lot two weeks from now.”
- On Guide: “Garden science, translated into plain steps.”

## Success criteria

The onboarding is successful if Momma D can explain the app back in one sentence:

“This tells me what to do in my garden today and helps me understand why.”

## Anti-goal

Do not turn the walkthrough into a product tour of every feature. The guide should reduce anxiety, not advertise complexity.
